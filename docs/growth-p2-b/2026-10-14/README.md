## 2. 家园与构图

主题是森林边缘刚刚开始生活的小家园。12×12正交地块，32px基础瓦片，原生土地384×384。

- 红顶木屋在视觉中心，前方接地点为世界像素 `[176,160]`，名义3×2占地，精灵左上 `[128,48]`。
- 乡间土石小路从南侧进入，向北通到门前台阶；转弯与端点由相邻道路决定。
- 七棵树围合西、北、东和前景边缘，使用两种不同轮廓；没有平均排列成素材矩阵。
- 花丛在门前、小路和信箱附近；三组灌木、八组草丛及少量石头填补环境层次。
- 右侧六格裸露土地和短栅栏提供“可以继续建设”的暗示，中央偏右留有草地空场。
- 总计32个独立对象实例：1屋、7树、17组植被、7件环境装饰。129格草地、9格道路、6格裸地。草地格数不等于可建造空格数；本轮没有正式碰撞计算。

## 3. 真正的场景结构

`src/growth/homestead/scene.json` 保存地形字符行和独立对象列表。`.`草地、`d`裸地、`p`道路；对象使用稳定实例ID、资源ID和地面锚点的网格坐标 `at`。

渲染顺序为地形 → 独立接地阴影 → 可选辅助网格 → 按地面深度排序的Sprite。地形逐格从图集取帧；房屋、树和装饰逐个绘制透明PNG。**整个家园没有烘焙成一张背景图。** 改动某个对象的 `at` 后刷新，可以移动该物体；已有单元测试验证移动木屋不改变地形或其他实例。

对象按 `groundAnchorY` 排序，同深度再按priority和ID稳定排序。树冠允许超出名义占地。场景中的树和装饰使用少量亚格偏移，避免机械对齐；这些偏移均对应整数原生像素。正式建造集成前，还需确定格点吸附、合法占地及装饰偏移规则。

相机提供总览、木屋近景、道路细节、缩放、鼠标/触控拖动和键盘方向键平移；有边界约束。桌面总览默认2×，320/390px窄屏总览0.5×，手机木屋近景2×。0.5×用于完整总览，会舍弃部分细节；像素品质应同时检查1×/2×及近景。整数放大使用最近邻，未拉伸素材长宽比例。

## 5. 地形生产与连接规则

地形由原创像素簇构图和自动连接规则结合制作，源参数是 `terrain-style.json`，源代码是 `produce_assets.mjs` 和 `src/growth/homestead/tile-rules.js`。没有简单色块占位、网格线贴图或模糊滤镜。

- 8种草地纹理：叶簇位置、密度和柔和色差不同，保留共同边界签名。
- 泥土47种、道路47种连接形态：N/E/S/W和四个对角；对角仅在其两条相邻边连通时启用。角形规则自动组成直线、转角、端点、交叉、外缘和内角。
- 针对场景中重复的长直道路，另提供2种内部纹理变化，边界签名保持一致。
- 共104个32×32图块，512×224图集，16列；单独PNG全部保留于 `terrain-tiles/`。
- 边缘保留约3px草地过渡，轮廓有受控1px起伏，纹理集中成簇，避免独立随机杂点。

当前道路与裸地分别向草地过渡。没有额外实现“道路覆盖裸地”的多层混合地形；二者在这个场景中由草地分隔。规则的像素接缝检查不等同于任意混合构图的美术验收。

## 8. 视觉检查与有限修整

通过实际场景截图检查了接地、比例、地形接缝、轮廓、图块重复、树冠遮挡及留白。修复了首轮横向栅栏的画布相机比例，以及石头/纵向栅栏裁切。Blender正交尺寸需按画布较大轴计算，不能把木屋的竖画布计算直接套到横向素材。

只进行了一轮场景美术修整：草叶纹理改为低对比连接簇、降低密度，给长直道路增加纹理变化，土地边缘添加受控像素起伏，并将接地阴影统一向右下偏移。没有更改已验收木屋，没有无限调图。

当前仍有主观或后续问题：

- 树冠偏圆润、色块层次较大，叶片细节密度低于木屋屋瓦；还需用户判断是否属于同一套足够精致的美术。
- 草地只有8种基础变化，长时间观察仍可能识别重复纹理；没有跨多格的大纹理变体。
- 野花仅一类组合，目前以少量重复簇构图；没有季节变体或动画。
- 纵向栅栏在正南机位较窄，需要未来实际长段摆放时继续检查可读性和连接锚点。
- 裸地造型受网格连接约束，仍有规则轮廓；不是手绘的大面积自然土壤地貌。
- 阴影为统一的简化接地层；不会计算树冠投影到房屋，也没有像素绘画级的局部形状修整。
- 手机完整总览细节较小，应结合近景评审。正式建造碰撞、命中蒙版、收纳/移动交互本轮未开发。

以上不通过降低木屋品质来掩盖。是否达到“愿意继续建设”的整体氛围，留给用户实际观察后判断。

## 9. 可复现生产过程

保留的核心脚本：

1. `build_assets.py`：逐项创建语义Mesh、材质、相机、原生画布、真实工程和原始渲染。
2. `produce_assets.mjs`：复用原木屋、规范化新Sprite、制作地形图块/图集、写资源清单。
3. `verify_models.py`：从已有工程重新打开，不重建几何，输出验证渲染。
4. `verify_assets.mjs` / `verify_browser.mjs`：技术检查及真实页面截图。
5. `scene.json` + `world.js` + `renderer.js`：独立可调整的布局、瓦片与Sprite组装。

脚本尽量使用相对于自身/仓库的路径；Blender与依赖路径在运行命令中配置。重复生产使用**新的输出目录**，拒绝覆盖已有工程或素材。示例（尚未占用这些示例目录）：

```sh
export PNGJS_MODULE=/Users/lyc/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/pngjs
/Users/lyc/Applications/Blender.app/Contents/MacOS/Blender \
  --background --factory-startup --disable-autoexec --python-exit-code 1 \
  --python docs/growth-p2-b/2026-10-14/build_assets.py -- \
  --output docs/growth-p2-b/2026-10-14/runs/reproduce-01/models
node docs/growth-p2-b/2026-10-14/produce_assets.mjs \
  docs/growth-p2-b/2026-10-14/runs/reproduce-01/models \
  public/assets/growth-p2-homestead-reproduce-01 \
  docs/growth-p2-b/2026-10-14/runs/reproduce-01/tiles
```

示例不会替换正式预览资源；生成到新目录后需有意识地选择对应清单才能使用。当前 `verify_assets.mjs` 与页面入口默认验证本次交付目录。脚本依赖已保留的P2-A相机/材质帮助函数；另一个工作区需要同时保留对应源码。

本轮所有新材质、模型和地形为原创，没有商业游戏贴图。地形源工程是参数与代码；没有宣称它是自动分层的Pixelorama/Aseprite工程。Blender原生工程真实可编辑，但没有进行用户人工GUI编辑验收。

工具购买与API费用为0。脚本内九项建模、保存与渲染合计计时0.473秒，不含启动、开发、授权等待、测试或美术调整；整体阶段壁钟见 `run-summary.json`，不要把批处理时间理解为首次设计耗时。
