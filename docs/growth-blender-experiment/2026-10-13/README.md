# 明日复：Blender 原创木屋生产实验

日期：2026-10-13。状态：**真实建模、渲染和编辑验证完成；候选美术，等待用户视觉验收。**

本轮只制作一栋木屋。红顶与蓝顶是同一栋建筑的材质版本。没有调用 PixelLab、图像生成服务或收费插件，没有接入 P1/P1.1，也没有提交或推送 Git。

## 1. 结论与实际能力边界

免费 Blender 已完成「脚本建模 → 可编辑工程 → 原生低分辨率渲染 → 确定性像素导出 → 方格场景 → 局部材质修改 → 重开与重建检查」整条流程。模型、材质、相机和最终精灵均有真实文件。

这证明 Blender 可以作为低预算的结构化建筑生产工具。尚未证明无需审美判断就能稳定批量生产商业级像素美术。屋瓦排列仍偏规整，建筑正面较对称，局部窗框细节在原生尺寸下较拥挤。它具有温暖、清晰的候选表现，但不能以文件导出或测试通过代替视觉验收。

## 3. 原创设计与真实编辑能力

木屋采用前向山墙、分片屋顶、错缝木板墙、框架立柱、石基与台阶，配有门框与门板、雨棚、铰链、门把、两扇暖色窗、窗框与格栅、百叶窗、阁楼窗、砖烟囱及盖沿、小花箱和灯具。没有复制《星露谷物语》的建筑或贴图。

工程包含 **271 个 Mesh 对象**，按语义集合组织：

| 集合 | 对象数 | 可以编辑的内容 |
| --- | ---: | --- |
| Foundation | 17 | 基座、石块、台阶 |
| Walls | 54 | 木墙、完整山墙、梁柱 |
| Roof | 115 | 完整顶面、屋瓦、屋脊、屋檐、门雨棚 |
| Door | 14 | 门板、门框、铰链、门把 |
| Windows | 38 | 玻璃、框格、窗台、百叶窗 |
| Chimney | 19 | 烟囱、砖块、顶部结构 |
| Decorations | 14 | 花箱、植株、灯具等 |

顶层为 `Building`。材料是原生 Blender 材料数据块；在材质节点的 **Asset pigment** 修改颜色。几何对象和部分 Bevel Modifier 保留可编辑性，不是 PNG 贴在一个平面上。模型没有制作室内、完整建筑信息模型或机械装配约束。

这提供的是**语义可编辑 3D 工程**，不是自动拆分出的多层 2D 像素工程。重新渲染可以保留结构修改；单个像素的艺术性修整仍需额外方案。

## 4. 投影、占地与像素输出

| 项目 | 当前候选规范 |
| --- | --- |
| 地图 | 32×32 正交方形地块 |
| 建筑视角 | 南侧正交相机，水平旋转 0°，俯角 38° |
| Sprite | 原生 96×128 RGBA PNG |
| 画布锚点 | 左上原点；`[48,112]`，前方地面接地点 |
| 逻辑占地 | 3×2 地块 |
| 基础比例 | 32 个输出像素 / Blender 世界单位，水平方向 |
| 光照 | 左上方 `[-3.5,-4,7]`；四档世界法线明暗材质 |
| 轮廓 | 最终输出增加 1 个原生像素的外轮廓 |
| 色板 | 明确的 32 色共享候选色板，屋顶使用其子集 |

相机没有采用等距 45° 水平旋转。建筑横轴保持水平，能看见屋顶与正立面，放入方形地面场景无需菱形网格。斜视相机会压缩建筑的 Y 深度；**3×2 是逻辑放置区域，并不意味着模型地面 Y 轴与方格背景逐像素等比例投影**。目前只验证视觉摆放，没有测试正式碰撞、遮挡排序或建造系统集成。

原始渲染直接为 96×128，不经过高分辨率缩小。模型中的屋瓦接缝与主要框架按最终像素宽度调整，以减少细碎采样。采用离散法线明暗材质，关闭间接颜色反弹，避免屋顶换色污染墙体。此风格不提供完整物理投影阴影；场景接地阴影是独立预览合成层。

Blender 原始 PNG 仍有采样色与半透明边缘，已完整保留。`pixel_export.mjs` 在**相同分辨率**执行 Alpha 阈值、固定色板映射、屋顶几何区域色板限制与外轮廓；没有重绘建筑、模糊缩放或人工像素涂改。480×480 模型预览使用另一相机，仅检查模型，不是游戏精灵的来源。

| 检查 | 暖红版本 | 深蓝版本 |
| --- | ---: | ---: |
| 原始渲染尺寸 | 96×128 | 96×128 |
| 原始可见 RGB 色数 | 2283 | 2184 |
| 原始半透明像素 | 760 | 760 |
| 最终可见色数 | 26 | 29 |
| 最终色板外颜色 | 0 | 0 |
| 最终 Alpha | 仅 0、255 | 仅 0、255 |
| 最终透明像素 | 3879 | 3879 |
| 最终包围盒 | x=3,y=4,w=90,h=110 | 相同 |
| 触碰画布边界 | 否 | 否 |

这些是技术检查，不自动判断建筑美感、像素簇质量或结构真实性。完整记录在两个 `*-sprite-quality.json` 中。

## 5. 屋顶修改与复现

实际重新打开原始 `.blend`，仅修改四个 `Roof_Color_*` 材料的色值，另存深蓝工程并重新渲染。无需重建整栋建筑。屋顶集合包括门雨棚，所以门雨棚也同步换色。

- 全部对象网格、变换、Modifier、材料指派、相机及非屋顶材质保持一致。
- 屋顶几何可见蒙版包含 3612 个像素，其中 3603 个 RGBA 像素变化。
- 屋顶以外 8676 个像素中，变化 **0**；Alpha 变化 **0**。
- 该结果来自两次独立渲染与同一导出流程，没有把原图墙体粘回去来隐藏修改影响。
- 原工程重开重渲、深蓝工程重开重渲、脚本从空场景重建：原始 PNG 与最终 Sprite 均与相应交付版本逐像素一致。

**26/26 检查通过**，见 `delivery/verification.json`。可重复性仅对本轮验证的 Blender 4.5.14 / CPU / 固定配置成立；没有声称跨版本、跨 GPU 也能得到相同像素。

早期物理间接光与采样方案曾产生 15～16 个屋顶外变化像素。相关失败检查和工程在 `final/`、`release/` 等试验目录保留。最终方案通过受控材质避免耦合，没有删掉失败记录。`drafts/`、`output/`、`final/`、`release/`、`candidate/` 是同一栋木屋的调试版本；本次交付以 **`delivery/`** 为准。

## 9. 本机复现方法

在项目根目录执行。使用新的目录名，保留 `delivery/`。脚本自行寻找安装的 Blender，也支持 `--blender` 或 `BLENDER_BIN`；没有硬编码本项目绝对路径，也没有网络调用。

当前 Codex 已有 PNG 依赖的位置如下；其他电脑应指向其已有的 pngjs 包，无需使用此机器的路径：

```sh
export PNGJS_MODULE=/Users/lyc/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/pngjs
python3 docs/growth-blender-experiment/2026-10-13/run_pipeline.py \
  --output docs/growth-blender-experiment/2026-10-13/runs/reproduce-01
node docs/growth-blender-experiment/2026-10-13/verify_outputs.mjs \
  docs/growth-blender-experiment/2026-10-13/runs/reproduce-01
node docs/growth-blender-experiment/2026-10-13/make_previews.mjs \
  docs/growth-blender-experiment/2026-10-13/runs/reproduce-01 \
  docs/growth-blender-experiment/2026-10-13/runs/reproduce-01/previews
```

若本地预览服务已经停止，可运行：

```sh
python3 -m http.server 5187 --bind 127.0.0.1 \
  --directory docs/growth-blender-experiment/2026-10-13
```

当前 5187 服务只开放实验目录。正式应用服务与业务文件未修改。Blender 原生工程可用已安装应用打开；本轮实际执行的是后台工程重开与渲染验证，未进行人工 GUI 编辑验收。
