2026-10-14：独立成长游戏的最新目标、验收状态、原生多Agent协作和后续任务以[Manager接管记录](../growth-game.md)为准。本文件继续保留P1阶段事实。

2026-10-10 更新：P1.1 交互修正和候选美术样板已实现，最新说明与验证见 [P1.1 记录](../growth-p1.1/README.md)。本文件保留 P1 阶段记录。

一个虚拟世界代表用户本人，与任何单个目标、任务或 V3 成长世界无关。本轮验证自由建造、空间规则、自动环境变化和地图扩张；没有奖励经济或任务接入。

## 本地访问

项目依赖已存在时运行：

```sh
npm run dev -- --host 127.0.0.1 --port 5186 --strictPort
```

原型：<http://127.0.0.1:5186/growth-p1>；原有应用：<http://127.0.0.1:5186/>。

只有 `src/main.jsx` 增加专用路径的懒加载分支。V3 App、目标、计划、任务和旧成长系统源码没有修改。

## 操作

1. 在基础建筑中选择小屋、书屋、茶屋或长椅。
2. 点击或触摸地图选择锚点，查看占地预览，再确认放置。绿色合法，红色显示越界或重叠原因。
3. 点击已有建筑，选择移动或收纳；收纳盒可以重新摆放同一建筑。预览和取消不会修改存档。
4. “让自然生长一次”会舒展植物或在空地增加植物，不改变建筑记录。
5. 进入扩张，选择现有土地旁的一个区域，确认后新增 8×8 格；可以在新土地继续建造，也可跨已开放区块的接缝建造。
6. 拖动地图平移；加减按钮支持从 6.25% 到 400% 的分档缩放（大世界可进一步缩小）；完整地图按钮按所有已开放土地、树冠和屋顶自动取景。
7. 预览选中后也可用方向键调整位置、Enter 确认、Escape 取消。

## 架构

| 文件 | 职责 |
| --- | --- |
| `src/growth/world.js` | 世界数据、纯命令、存档结构验证 |
| `src/growth/grid.js` | 8×8 区块、网格、完整占地、相邻区域和碰撞 |
| `src/growth/buildings.js` | 四类建筑与占地、素材配置 |
| `src/growth/nature.js` | 独立环境状态及模拟变化 |
| `src/growth/view.js` | 共用 2:1 斜俯视投影、屏幕反算网格、相机取景与缩放档位 |
| `src/growth/isometric-art.js` | 与地面轴一致的临时建筑像素图、地块和无平滑栅格绘制 |
| `src/growth/renderer.js` | 像素图集加载、草地水面绘制、对象深度顺序与预览渲染 |
| `src/growth/WorldMap.jsx` | Canvas、指针/触摸、平移缩放和键盘交互 |
| `src/growth/persistence.js` | 版本键、序列化、读取验证和并发保存检查 |
| `src/growth/useWorld.js` | 保存成功后提交 React 状态、失败重试、跨页冲突 |
| `src/growth/WorldPrototype.jsx` | 原型界面与操作编排 |
| `src/growth/styles.css` | 原型范围内的桌面/手机样式 |

世界结构包含版本、区块坐标、建筑、自然细节和模拟成长状态，没有 `goalId`、目标或任务数组。区块允许负坐标，建筑坐标为整数网格；所有占地单元必须位于开放土地内。坐标验证的安全上限为绝对区块坐标 10,000；本轮没有大地图性能承诺。

## 保存与恢复

- 独立 `localStorage` 键：`mingrifu-growth-world-p1-v1`，结构版本为 1。
- 不读写 `mingrifu-v3-demo-1`、其草稿键或历史 V4 存储。
- 每次命令先校验并保存，再更新可见世界。写入失败时保留原状态和待重试候选，显示“重试保存 / 放弃本次变化”。
- 发现其他标签页更新时暂停写入，重新读取后继续，避免覆盖另一页。
- 损坏、未知版本或无法访问的存档不会被自动重置；显示只读初始预览并保留原存档。
- 首次打开的初始世界是确定性数据；第一次有效操作后写入存档。
- 在相同浏览器和相同来源地址下，刷新和重新打开会恢复存档。不同端口/域名、无痕模式、浏览器清理或禁用存储会影响保留；没有账号与云同步。

## 验证方式

```sh
npm test
npm run build
node scripts/verify-growth-p1.mjs
```

浏览器脚本使用环境已有的 Playwright 和 Chrome，创建隔离上下文，不连接用户的浏览器个人资料。若 Playwright 不在项目依赖解析范围，可设置 `PLAYWRIGHT_MODULE` 指向已安装的模块；无需修改产品依赖。`BASE_URL` 可指定服务地址，`QA_OUTPUT` 可指定截图和结果输出目录。

领域测试位于 `tests/growth-p1.test.mjs`；浏览器验收结果及截图位于本目录的 `verification.json` 与 PNG 文件。结果文件只代表对应执行时的版本，不替代真机验证。

## 临时素材与本轮限制

- 植物来自历史 CC0 图集；建筑现由 `isometric-art.js` 按统一投影生成临时像素图，来源见 `public/assets/growth-p1/SOURCE.md`。它们用于验证交互，并非最终美术，后续仍需专用建筑、植物与地表过渡资产。
- 使用 2D Canvas 的 2:1 斜俯视画面，土地、建筑占地、屋顶与点击定位共用投影；没有真实 3D 相机、复杂地形、天气或大型动画系统。缩小使用最近邻采样；很低倍率会减少可辨认细节。
- 建筑覆盖植物所在格时植物会让位；建筑本身不会被自动成长移动、收纳或删除。
- 没有旋转、批量选择、撤销/重做、自动道路、存档导出或正式数据迁移工具。
- 触摸支持点击预览、确认和单指拖动平移；缩放使用按钮，不实现双指手势。
- 完整地图可自动缩小总览，放大后可平移查看；环境细节与区块遍历尚未针对长年积累优化。
- 真实手机 Safari、Android Chrome、微信浏览器以及跨设备持久化尚需验证。

## 下一轮建议

优先收敛统一视角的独立像素资产、地块衔接与触摸操作反馈，再验证大地图性能、撤销/重做及可恢复的存档导出。若正式版需要大量对象、动画与持续更新，评估 React 界面配合独立场景层（例如 PixiJS 或 Phaser），保留纯世界数据、网格规则和存储接口；本轮没有引入引擎或新增依赖。正式奖励、努力映射和跨设备保存应另行设计，不能从 P1 的模拟次数推导。
